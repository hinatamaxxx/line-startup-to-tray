## LINEの自動更新後に通常表示へ戻る問題への対策

Windowsへのサインイン時に、LINEの画面を出さずに通知領域へ起動する非公式ツールです。

### この版の変更

- LINE自身が更新プログラムを起動し、新しいLINEへ切り替えるときにも、表示制御を引き継ぐようにしました。
- 32bitの更新プログラムが使う `CreateProcessA` と、Unicode版の `CreateProcessW` の両方に対応しました。
- Windowsの起動登録を独立した `WindowsLineStartToTray` 項目へ移しました。LINEが自分の起動コマンドを書き換えても本ツールの登録は残ります。
- LINE標準の起動項目はWindows側でOFFにし、通常起動との重複を防ぎます。旧版からの更新でも導入前のバックアップを引き継ぎます。

ウィンドウを一定間隔で探す監視ループや、起動後に待って画面を閉じる処理は追加していません。

### ダウンロードとセットアップ

**Assetsの `WindowsLineStartToTray-Setup-0.2.0-preview.6.exe` をダウンロードしてください。** `Source code (zip)` や `Source code (tar.gz)` は開発者向けです。

1. LINEの自動ログインをONにし、通知領域のメニューからLINEを「終了」します。
2. ダウンロードしたEXEを開き、「セットアップ」を押します。旧版を使っている場合も同じ手順で更新できます。
3. 「LINEを起動」を押し、画面が出ず、通知領域のアイコンをダブルクリックすると開けることを確認します。
4. 都合のよいときにPCを再起動して確認してください。

管理者権限、コマンド入力、追加のダウンロードは不要です。Windowsの「設定 → アプリ → スタートアップ」では、**`WindowsLineStartToTray` がON、`LINE` がOFF** の状態にします。セットアップが設定するため、通常は手動変更の必要はありません。

### 検証状況

2026年10月1日の実機ログで、補助EXEと旧LINEにはDLLが読み込まれた後、26.5.0.3975への自動更新で起動し直されたLINEにはDLLがないことを確認しました。実際のLINEの起動登録も元のランチャーへ戻っていました。

修正版は、更新経路を模したテスト用アプリで、32bitランチャー → 64bit LINE → 64bit管理プロセス → 32bit更新プログラム → 64bit更新後LINEという経路を確認しています。初回表示の抑制と、その後の再表示も通っています。LINE自身のRun値の上書き、旧版からの移行、二重セットアップ、導入前の設定への復元も、独立したテスト領域で確認しました。

**この版での実際のLINE更新の再実行と、修正後のPC再起動を伴う最終確認は未実施です。** 検証範囲を明記したプレビュー版として配布します。LINEの内部構造の変更で動作しなくなる場合や、通知領域アイコンの未読バッジが反映されない場合があります。

コード署名はありません。照合用の `SHA256SUMS.txt` を添付しています。LINE本体やログイン情報は同梱していません。
